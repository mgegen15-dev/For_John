Auditor's Guide

For a third-party reviewer. Version 1.1, frozen on November 27, 2026 (git tag v1.1). Check against that tag, not the live main branch, so that your findings line up with what you are reading. Version 1.0 (tag v1.0, November 23, commit aa55a1b) is the original review without the research engine. A freeze prepared on November 25 was never tagged and is superseded.

This project makes many claims across 36 reports and 2 briefs. This page lists the 18 from the original review that matter most, then how to check the research engine added in version 1.1. The 18 are the ones the one-page summary, the website and the ranked leads depend on. For each one it gives where the claim is made, its primary source, and the fastest way to check it. If these hold, the project's main conclusions hold. If any fail, please tell us.

Before You Start

  • Get the frozen version:
    git clone https://github.com/mgegen15-dev/For_John
    
    cd For_John && git checkout v1.1
  • Set up: Python 3.10 or newer, plus pip install -r requirements.txt (pandas, numpy, scipy, matplotlib, h5py and the Markdown tools that build the website; versions pinned).
  • Check the data is unchanged: run python3 tools/build_manifest.py (it rewrites DATA_MANIFEST.md and data/raw_checksums.txt), then git diff DATA_MANIFEST.md to compare with the checksums committed at v1.1. Raw downloads are not in git, so they must be re-downloaded. Live databases change, so expect small differences from the retrieval dates listed there.
  • Read first: HOW_THIS_WAS_MADE.md (methods, limits, how AI was used) and SUMMARY.md (the claims in plain language).
  • Earlier internal checks: research_notes/Audit/ holds the AI-run audits and their findings. They are a record, not a substitute for your review.

Labels used in the reports:

  • (registry): an official database record.
  • (paper, full text): read in the full published paper.
  • (paper, abstract only): read only in the abstract.
  • (preprint, abstract only): an unreviewed preprint.
  • (press release only): no peer-reviewed source.
  • (our calculation): computed by this project.

Claims labelled abstract-only, preprint or press-release-only are the weakest, and the most worth checking.

The Research Engine (Added in Version 1.1)

Twenty cycles, each in research_notes/Engine/cycle-NN-*/PREREGISTRATION.md with a report in reports/Engine cycle N - ....md. The engine's central promise is that each plan was committed before its data were opened. That is checkable:

  • Order of events. For each cycle, compare the commit time of its PREREGISTRATION.md (git log --format="%h %cI" -- research_notes/Engine/cycle-NN-*/PREREGISTRATION.md) with the first commit of its data and script (git log --diff-filter=A --format="%h %cI" -- tools/engine_cycleNN*; cycle 6 shares cycle 5's script, tools/engine_cycle05_06_depmap.py). The plan should come first. Changes made after the plan are listed under "Deviations" in each file. Commit times are set by the committer's clock, so they show order within this repository, not proof against a determined forger.
  • History rewrite on November 27, 2026. Two early files with one row per patient (data/engine/cycle03/patients.csv and data/engine/cycle07/patients.csv, derived from public cBioPortal data and removed from the live files on November 25) were also removed from the git history, so that the engine's cycle 3 and 7 outputs publish only counts. Open-access TARGET-OS clinical files used by the survival analysis remain in data/survival_raw/, as in version 1.0. The rewrite started at the first commit that added one of them (November 24). Everything before it is unchanged, including the v1.0 tag. Every later commit has a new ID, but its author, date, message and all other content are unchanged. The old and new ID of every rewritten commit are listed in data/commit_id_map_2026-11-27.csv, and the commit IDs cited in reports and pre-registrations have been updated to the new ones. The original commits were signed; the rewritten ones are not, because a signature cannot survive a rewrite. Commits made after the rewrite, from 07ef3ed on, are signed again and are not in the map. Clones made before November 27 still hold the old commits; please re-clone.
  • Re-running. Each report's last section gives the commands. Most need the raw downloads listed in DATA_MANIFEST.md, which are not in git.
  • Predictions. P15 to P55 in PREDICTIONS.md were written before each cycle's data; outcomes are recorded there with the rule each was judged by.

Known Weak Points

These are the places we already know the work is weakest:

  • Abstracts, not full texts. Many papers could be read only as abstracts, because some publishers block automated access.
  • Keyword tagging. Paper types and trial scope were assigned by keyword rules. The internal audit found roughly 1 in 4 to 1 in 3 tags wrong in a small hand sample.
  • Gene mislabelling. Automated text mining mislabels some genes. A correction table is in tools/literature_map.py, but more errors likely remain.
  • Narrow registry coverage. ClinicalTrials.gov only; European-only and China-only registries were not searched systematically.
  • Unverified sources. Several leads rest on press releases or web listings: the Colorado State dog studies, and the OST-HER2 vaccine results.
  • Trial classification by one reader. The trial counts in engine cycles 4 and 7 rest on one reading of each registry record. One error was found and corrected on November 25, 2026 (see the cycle 4 change log), and independent checks on November 26 and 27 found one more in each of cycles 7 and 12, now corrected (see their change logs).
  • Unplanned observations. Some engine reports describe things that were not in the plan (MCL1 in cycle 7, the microsatellite check in cycle 9). They are labelled as such and should not be read as results.
  • Deviation records. For cycles 1 to 3 the Deviations sections were committed before the results; for cycles 4 to 9 they were first committed together with the results, so git cannot show which came first. Changes made after a run are labelled as such.
  • Not independent people. All internal checks were run by AI models, not by independent people. Your review is the first independent check.
